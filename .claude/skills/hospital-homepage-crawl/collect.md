# 홈페이지 데이터 수집 플레이북

**전제: 공식 홈페이지 URL이 이미 확정됨** (SKILL.md §1에서 확보·검증, `homepage_url`·`url_source`·`url_confidence` 기록 완료). 이 파일은 그 URL의 홈페이지에서만 데이터를 수집해 정규화 JSON을 만드는 절차다.

- 데이터는 **공식 홈페이지에서만** 추출한다(블로그·SNS·지도·포털은 출처가 아니다).
- 참조 카탈로그: [`aesthetic_products.json`](reference/aesthetic_products.json), [`aesthetic_equipments.json`](reference/aesthetic_equipments.json)
- 출력 스키마: [`output_scheme.py`](reference/output_scheme.py) · 샘플: [`sample_output.json`](reference/sample_output.json) · 저장: `/output/{병원이름}_{병원ID}.json`

## 1. 페이지 라우팅 (방문 순서)
홈페이지 구조는 제각각이지만 정보 종류별로 다음을 반드시 확인한다.
1. **home** — 전체 네비게이션 파악, 다국어 스위처 유무
2. **병원 소개 / story, intro, doctor 등** — 운영정보(대표·사업자번호·전화·영업시간·주차·교통·시설) + 의료진
3. **시술·장비 목록 / contents 등** — 제품·장비명 수집
4. **시술 상세 페이지** — ⚠️ 반드시 본문 진입. 병원이 **자체 브랜드 시술명**(마케팅 네이밍)을 짓는 경우가 많아, 실제 장비·제품명이 목록이 아니라 **시술 설명 본문 안에만** 드러난다. 상세 본문을 끝까지 읽는다(예: "우마카세 리프팅" 설명 속 티타늄2·울쎄라2프라임).
5. **가격 + 비급여진료(안내) / event, promotion 등** — 가격 확인. ⚠️ 성형외과·외과 계열은 이벤트 페이지에 가격이 없어도 **"비급여진료비용 안내"** 페이지(법정 고지 의무)에 일부 시술 가격이 **텍스트**로 있다. 푸터/하단 링크에서 `비급여`·`nonpay`·`진료비용`을 찾아 반드시 방문한다.

각 페이지에서 탭·아코디언·"더보기"를 클릭해 숨은 콘텐츠까지 펼친다. 동적 로딩은 `browser_wait_for`.

> **별도 도메인 분원 처리**: 비수술(쁘띠/필러·톡신·레이저) 부문이나 특정 시술이 **다른 도메인**으로 운영되는 경우가 있다. 홈페이지-한정 정책상 기본은 **크롤링 범위 외**로 두되, 제품·장비 매칭 대상이 거기 몰려 있을 수 있으므로 `crawl_metadata.notes`에 도메인과 "동일 병원으로 묶을지 정책 결정 필요"를 반드시 기록한다. 임의로 크롤링하거나 무시하지 말 것.

## 2. 추출
원문 그대로 추출하고 번역·요약·정규화는 나중에 한다.

## 3. 카탈로그 매칭 — 핵심
단순 substring 매칭은 약하다. 다음 규칙을 모두 적용한다.
- **한↔영 교차 매칭**: 사이트 표기 ↔ 카탈로그의 한글/영문명을 양방향으로 대조.
  - `에코2`/`Eco 2` → `eCO2(이코투)`
  - `Co2 레이저` → `CO₂ 프락셔널`
  - `테오시알`/`Teosyal` → `테옥산 RHA`
- **유니코드 정규화(NFKC)**: `CO₂`↔`CO2`, 전각↔반각, 첨자 통일 후 비교.
- **수식어·접미사 제거**: `디스커버리 루비` → `루비 레이저`, `슈링크 유니버셜` → `슈링크`, 모델 넘버(`인모드 포마/FX`) 유연 처리.
- **시술-장비 연결 추출**: 시술 설명 안의 장비명도 equipment로 잡고, treatment의 `equipment_name`에 연결한다.
- **본문 속 제품·브랜드 열거**: 시술 설명·상세 본문 안에 나열된 개별 제품/브랜드명(특히 실리프팅 봉합사: 실루엣·울트라V리프트·브이락·POD·오메가/테스/미스코/금실 등)을 시술명 하나로 뭉뚱그리지 말고 **각각** 추출한다. 카탈로그에 없으면(봉합사·지방분해 등은 카탈로그 범위 밖) 버리지 말고 `unmatched_products`/`unmatched_equipments`에 개별 항목으로 기록한다.
- **무누락 원칙**: 매칭 실패해도 버리지 말고 `unmatched_*`에 `raw_name`·`category_guess`·`context`로 기록한다.
- **보수적 판단**: 발음만 비슷하고 동일 확신이 없으면 매칭하지 말고 unmatched로 두되 context에 의심 근거를 남긴다(예: `노블렉스` vs 카탈로그 `Nordlys` — 보류).
- **브랜드 다중 라인**: 브랜드만 있고 세부 라인이 불분명하면 사이트의 카테고리 맥락에 맞는 대표 제품으로 매칭(예: 필러 섹션의 `벨로테로` → `벨로테로 밸런스`).
- **이미지 기반 상세 페이지**(시술 설명이 그림으로만 된 사이트): 시술 상세 페이지가 수십 개이고 본문이 이미지뿐이면 **기본은 home 카드·메뉴 라벨·대표 페이지의 시술/제품명으로 라벨 매칭**한다(전수 vision 판독은 비용 과다). 단 **세부 라인 특정이 사업상 중요**하거나(예: 자사 취급 제품의 라인 구분: 울트라콜 100/200, 쥬비덤 볼루마/볼륙스), 라벨만으로 매칭이 모호한 핵심 항목은 **그 페이지만 골라 캡처→vision 판독**해 확정한다. 라벨로만 매칭한 항목은 `context`에 "라인 미특정, 대표 매칭"을 남기고 `verification_status`를 적절히(보통 `verified`이되 라인 추정이면 `inferred`) 표기한다.
- **제휴사·파트너 배너 활용**: 홈/푸터의 제휴 브랜드(예: 멀츠·솔타·클래시스·파마리서치·휴젤)는 장비·제품의 제조사 매칭 신뢰도를 보강하는 단서다. 단 제휴사만으로 특정 제품(예: 보톡스 제조사)을 단정하지 말고, 사이트 표기와 함께 교차 확인되는 경우에만 매칭에 반영한다.

## 4. 가격
- 가격은 `treatment.price` 객체에 담는다: 원문은 `price.text`, 숫자는 정수(원)로 `price.low`/`price.high`(범위가 아니면 high=null 또는 low와 동일), 단위는 `price.unit`(회/cc/샷/패키지 등), 이벤트가 여부는 `price.is_event_price`.
  - "5~30만원" 같은 **범위 가격**은 `low=50000, high=300000`으로 분해한다(단일 정수에 욱여넣지 말 것).
  - 이벤트 기간·세션 수는 `treatment.package.event_period`/`sessions`/`duration_months`에 구조화한다(treatment_name·notes 문자열에 묻지 말 것).
- 가격이 **이미지로만**(이벤트 배너·프로모션 표·비급여 표 이미지 등) 제공되면 그냥 null 처리하지 말고 **vision으로 판독**한다: 해당 이미지 요소를 `browser_take_screenshot`(element 지정)으로 저장한 뒤 `Read`로 읽어 가격·시술·구성품을 추출한다. 추출한 값은 일반 텍스트 가격과 동일하게 `price.text`/`low`/`high`/`unit`·`package`에 담고, `verification_status`는 `verified`로 둔다.
  - `notes`에 "가격을 ○○ 이미지에서 vision 판독" 출처를 반드시 남긴다(판독 근거 추적용).
  - 이미지가 **흐릿·잘림·일부만 노출**되어 신뢰 판독이 어려우면 그 항목만 `price.*` null + `notes`에 "이미지 판독 불가" 사유를 남긴다(불확실한 숫자를 추측하지 말 것).
  - **고정 오버레이 가림**: 페이지의 고정(quick-menu·상담폼) 바가 이미지 일부를 덮으면, 그 이미지의 **원본 URL로 직접 이동**하거나 오버레이를 숨긴 뒤 재캡처한다.
  - **초장축 이미지 분할 캡처**(이벤트/가격이 height 수천~1만px 세로 한 장에 다 들어있는 경우): 통째로 `Read`하면 다운스케일(최대변 ~1568px)로 글자가 뭉개져 판독 불가하다. `browser_evaluate`로 그 `<img>`를 **폭 800px·`position:fixed`·`left:0`·`top:0`**로 고정한 뒤, `top`을 약 1300~1400px씩 음수로 이동(`top:-1350px`, `-2700px`…)시키며 **구간별로 viewport 캡처→Read**해 순차 판독한다(겹침 ~100px). 가능하면 같은 가격이 텍스트로도 있는 페이지(지점안내·상세표)와 **교차검증**한다.
- 이벤트/시술 페이지에 가격이 없어도 **비급여진료비용 안내 페이지**(§1 라우팅 5번 참조)는 가격의 유일한 출처인 경우가 많으니 반드시 확인한다(텍스트·이미지 모두 위 규칙대로 처리).

## 5. 정규화 포맷
- 전화 `02-0000-0000`, 사업자번호 `000-00-00000`
- 영업시간: 요일별 `open/close/break_start/break_end` (HH:MM, 휴무 null)
- 주소: 입력 주소를 `address.{sido,sigungu,eupmyeondong,road_address,latitude,longitude}`로 구조화해 출력에 보존한다(좌표·시군구는 DB 적재 시 재조인 불필요하도록).
- 여러 페이지의 동일 제품/장비/의료진은 하나로 통합하되, **출처 페이지는 버리지 말고** 각 항목의 `sources[]`(`{channel,url,evidence}`)에 모두 누적한다. 본문 언급 횟수는 `mention_count`(영업 신호)에 기록.
- 항목별 신뢰도는 `verification_status`(`verified`/`unverified`/`inferred`)로 남긴다.
- **신원확인 최종 확정**: SKILL.md §1의 예비 판단을, 실제 수집한 사업자정보/운영정보(병원명·대표·사업자번호·주소)와 입력 CSV를 대조해 `identity_status`(`match`/`mismatch`/`partial`)로 확정한다.
- **URL 단계 외 필드**: 크롤링 중 발견한 `blog_url`·`sns_url`·`alternative_urls`(언어 버전·구도메인 등)·`branches`(단독/지점/별도 도메인 분원)를 채운다.

## 6. 완전성 체크리스트 & notes
출력 `crawl_metadata.completeness`에 7항목을 채운다. 수집되면 true:
`operation_info / doctors / products / equipments / treatments / prices / language_support`

**`crawl_metadata.notes`는 비워두지 말 것.** 최종 JSON을 내기 전, 다음 판단 근거를 반드시 문장으로 남긴다:
- 가격: 텍스트/이미지/없음 구분과 출처 페이지
- 매칭: 한↔영 매칭으로 확정한 항목, 보류(unmatched)한 항목과 그 이유
- 별도 도메인·다국어 등 정책 결정이 필요한 사항(§1 라우팅의 별도 도메인 처리 참조)
- 미방문/미확인으로 남긴 영역

## 7. 마무리
- 산출 JSON을 `/output/{병원이름}_{병원ID}.json`에 저장한 뒤 **반드시 `output_scheme.py`로 검증**한다(검증 커맨드는 CLAUDE.md 참조).
- 검증이 끝나면 Playwright로 연 브라우저를 **반드시 `browser_close`로 종료**한다.
- 캡처한 스크린샷 등 임시 아티팩트(`.playwright-mcp/`, 가격 판독용 이미지 등)는 정리한다.
